## 一、许可证结构：为什么本项目必须是 AGPL-3.0

| 层 | 组件 | 许可证 | 对本项目的要求 |
|---|---|---|---|
| 本程序代码 | `webapp/`、`launcher.py`、`translate.py` | **AGPL-3.0**（我们选择与上游一致） | — |
| 核心库（以库形式导入） | BabelDOC 0.6.2 | AGPL-3.0 | 整体作品须以 AGPL-3.0 授权；分发须提供对应源码 |
| 核心库 | PDFMathTranslate-next 2.9.0 | AGPL-3.0 | 同上 |
| PDF 引擎 | PyMuPDF 1.25.2 | AGPL-3.0 | 同上（这是"必须 AGPL"的第三个来源） |
| 其余依赖 | onnxruntime(MIT)、numpy(BSD) 等 40 余项 | 宽松许可 | 保留版权与许可声明 |
| 版面模型 | DocLayout-YOLO ONNX 权重 | Apache-2.0（上游仓库标注） | 可再分发，需保留声明 |
| 多语言字体 | BabelDOC-Assets（34 个字体） | 各自开源许可（多为 OFL/Apache） | **需保留各自版权声明，不得单独售卖字体** |

**关键结论**：由于同时链接了三个 AGPL-3.0 组件，本项目**不能**以 MIT/Apache 发布，
也不能闭源。这不是我们可以选择的项，而是许可证的强制结果（AGPL-3.0 第 5(c) 条）。

## 三、检查中发现并已修正的问题

1. **明文 API Key 曾出现在测试脚本中** —— 已删除该文件，并确认全仓库无任何 `sk-` 开头的密钥；
   仓库将加入 `.gitignore` 与提交前扫描建议（见下）。
2. **`LICENSE` / `THIRD-PARTY-NOTICES.md` 缺失导致打包失败** —— 已补齐，并纳入构建流程强制存在。
3. **第三方许可清单靠记忆填写不可靠** —— 改为 `build/gen_third_party_notices.py` 从已安装包元数据自动生成，
   歧义项（peewee/scipy/scikit-image/Levenshtein/pymupdf）**逐个人工读取包内 LICENSE 文件核实**。
4. **上游 API 政策**：BabelDOC README 声明其自身 API 属内部接口，推荐经 pdf2zh-next 调用。
   本项目主翻译链路已走 pdf2zh-next 的 `do_translate_async_stream`；
   仅资源预下载脚本调用 `babeldoc.assets`（该功能 pdf2zh-next 未提供等价公开入口，已在代码注释中说明）。
5. **输出 PDF 的 AI 生成标注**：BabelDOC 会在产物中写入 producer 标记（提示内容为机器翻译）。
   本项目默认关闭水印以保证可读性，但**保留** producer 标注。若你希望更保守，可改用默认水印模式。
